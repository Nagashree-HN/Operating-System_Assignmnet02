Task 01 - GDB Questions

1. Which function called syscall?
Answer: The function that called syscall() was usertrap().

2. What is the value of p->trapframe->a7 and what does it represent?
Answer: The value of p->trapframe->a7 was 0xf, which is 15 in decimal.
This value represents the system call number for open(). The a7 register tells the kernel which system call the user program is requesting.

3. What was the previous mode the CPU was in?
Answer: The CPU was previously running in user mode. The SPP bit in the sstatus register was 0, which shows that the trap came from user mode before entering supervisor mode.

4. What assembly instruction caused the panic, and which register corresponds to num?
Answer: The kernel panicked at the instruction lw a3, 0(zero).
This instruction tries to load a 32-bit value from memory address 0 into register a3. Since this instruction was generated from the statement num = *(int *)0;, the register a3 corresponds to the variable num in my compiled code.

5. Why does the kernel crash?
Answer: The kernel crashes because the statement num = *(int *)0; tries to read data from memory address 0. Address 0 is not mapped as valid kernel memory, so the CPU generates a load page fault. In my run, scause was 0xd, which represents a load page fault, and stval was 0x0, confirming that the invalid memory address was 0.

6. What is the name of the process that was running when the kernel panicked? What is the process id (pid)?
Answer: The process that was running when the kernel panicked was init, and its process ID was 1. I confirmed this in GDB using p p->name and p p->pid.
